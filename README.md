# eltex-automation

Массовая настройка коммутаторов Eltex MES по SSH через [netmiko](https://github.com/ktbyers/netmiko).

**Статус:** в разработке. Фаза 1 — capture: снятие сырого вывода команд с устройства и проверка его целостности.

## Требования

- Linux, Python 3.14 (проверено на Arch Linux)
- сетевой доступ по SSH к устройствам (порт 22)
- учётная запись с привилегиями (на тестовом стенде enable не требуется)

## Установка

```bash
cd ~/projects/eltex-automation
python3 -m venv .venv
source .venv/bin/activate
pip install netmiko
```

На Arch Linux установка пакетов в системный Python запрещена (PEP 668), поэтому окружение обязательно отдельное — `.venv` в корне проекта.

## Учётные данные

Пароль **не хранится на диске**. Скрипт спрашивает его при запуске и держит только в памяти процесса:

```python
password = getpass.getpass("Пароль устройства: ")
```

Файл `.env` в этом проекте не используется. Для будущих пакетных прогонов по десяткам устройств планируется внешнее хранилище (pass / sops / Vault).

## Запуск

```bash
cd ~/projects/eltex-automation
source .venv/bin/activate
python lab/01_capture.py
```

Скрипт спросит пароль и подключится к устройству. Журнал разговора с устройством пишется в `out/session.log` (в git не попадает).

## Структура проекта

```
lab/          скрипты и заметки; lab/notes/ — личные заметки, вне git
inventory/    описание устройств (пока пусто)
out/          снятый вывод и журналы сессий (в git не попадает)
secrets/      креденшелы (в git не попадает; при getpass не требуется)
```

В `.gitignore` исключены `.venv/`, `.env`, `out/`, `secrets/`, `__pycache__/` и `lab/notes/`.

## Особенности Eltex MES (проверено на MES3300, 6.6.12.1)

- `terminal ?` показывает только `datadump`, `history`, `no`, `prompt`, `width`. Команды `terminal length` у Eltex нет — приём `terminal length 0` неприменим.
- Пагинацию снимает `terminal datadump`; драйвер netmiko `device_type="eltex"` отправляет эту команду сам при подключении.
- Неизвестная команда даёт `% Unrecognized command` — ошибки можно распознавать по `%` в начале строки.
- Имя порта пишется по-разному: `gi1/0/22` в `show interfaces status` и `GigabitEthernet1/0/22` в `show running-config` — нужен единый канонический вид.
- `save_config()` в драйвере netmiko для Eltex не реализован — конфиг сохраняется вручную (`copy running-config startup-config`).

## План

1. **capture** (в работе) — снять сырой вывод и проверить его целостность: нет `More:`, в конце файла приглашение устройства.
2. **разбор** — превратить вывод в структуру данных (VLAN, порты, режимы доступа и trunk).
3. **desired state** — описать целевую конфигурацию в YAML, применить её и сверить с фактическим состоянием устройства.
4. **массовый прогон** — по описанию устройств из `inventory/`.
5. **Ansible-обёртка** — отложена, отдельная фаза.
